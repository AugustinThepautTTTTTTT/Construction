# Renovate a room

Turn an incomplete room brief into only the useful outputs the user requests. Prefer a safe, actionable answer over an aspirational but unverifiable one.

## Plan the conversation

1. Identify the requested deliverable. Do not automatically produce every possible artifact.
2. Extract known facts: location, room type, dimensions, photos, household, current condition, goal, style, budget, timeline, DIY/trade split, and immovable elements.
3. Ask no more than three questions at a time, and only when their answers materially change the result. State reasonable assumptions instead of prolonging intake.
4. When photos are present, separate observations from inferences. Never infer hidden structure, services, dimensions, damage, or code compliance.
5. Produce the requested output using the patterns in `references/deliverables.md`.

## Apply safety boundaries

- Label concepts as illustrative and budgets as indicative.
- Recommend on-site validation for structure, demolition, load paths, electrical, gas, plumbing, waterproofing, fire safety, ventilation, hazardous materials, and permits.
- Never advise bypassing a regulation, safety device, licensed trade, or product instructions.
- Recommend urgent local professional help for suspected gas leaks, live electrical hazards, instability, fire, flooding, or disturbed asbestos/lead/mold.
- Preserve the user's intent while offering a safer alternative when a requested method is unsafe.
- Never invent product prices, stock, contractor quotes, certifications, or exact code requirements.

## Format the result

Lead with the recommendation. Use short headings, bullets and tables. Include assumptions and a short “verify before work” section. Use the user's currency and units; otherwise ask or label the chosen defaults.
